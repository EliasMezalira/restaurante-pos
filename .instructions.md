# 🏪 Restaurante POS - Instruções de Implementação

## Padrão Arquitetônico
Este projeto segue arquitetura em **camadas com Quarkus + Hibernate Panache + PostgreSQL**.

Estrutura de fluxo:
```
REST Controller → Service (lógica) → Repository (dados) → Entity (JPA) → BD
```

## 📋 Regras de Implementação CRUD

### Arquivos Obrigatórios para Cada Entidade
1. **Entity** → `model/entity/{Name}.java`
2. **Request DTO** → `model/request/Create{Name}Request.java`
3. **Response DTO** → `model/response/{Name}Response.java`
4. **Repository** → `repository/{Name}Repository.java`
5. **Service** → `service/{Name}Service.java`
6. **Controller** → `controller/{Name}Controller.java`

### 5 Operações CRUD Obrigatórias
- `criar(request)` → POST
- `obterPorId(id)` → GET /{id}
- `listar()` → GET
- `atualizar(id, request)` → PUT /{id}
- `deletar(id)` → DELETE /{id}

### Convenções de Nomenclatura
- **Tabelas**: snake_case (`usuario`, `garcom`, `menu`)
- **Classes**: CamelCase (`Usuario`, `Garcom`, `Menu`)
- **Controllers**: `{Name}Controller`
- **Services**: `{Name}Service`
- **Repositories**: `{Name}Repository`

### Regras de Código
✅ Validação sempre na Service, não no Controller
✅ Retornar Response DTOs, NUNCA Entity diretamente
✅ IDs em Response: usar `BigDecimal`
✅ Respostas sensíveis (senhas): NUNCA expor
✅ Exceções: lance `IllegalArgumentException` na Service
✅ Controller: trate e mapeie para HTTP status (400, 404, 500)

### Banco de Dados
- Driver: PostgreSQL JDBC
- ORM: Hibernate com Panache
- Migração: Liquibase
- Scripts: `src/main/resources/db/migrations/{seq}-{name}.sql`

### Exemplo Base
Veja `UserController.java`, `UserService.java`, `UsuarioRepository.java` como modelo.
